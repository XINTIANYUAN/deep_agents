# Task6 课程反馈

本次学习范围是[第 6 章：异步子 Agent](https://datawhalechina.github.io/deepagents-in-action/chapters/ch06-async-subagents/)和[第 7 章：Skills](https://datawhalechina.github.io/deepagents-in-action/chapters/ch07-skills/)。以下反馈结合本项目的版本约束与本地实验设计。

## 有帮助的内容

第 6 章把 Agent Protocol、Agent Server 和追踪系统分开介绍，并提供故意等待的最小 worker，适合先验证异步机制，再替换成复杂研究任务。对 worker slots、完整 task ID 和取消缓存的提醒很具体。尤其是“用 check 再查服务端，list 可能复用 cancelled 缓存”，直接影响验收结论。

第 7 章把元数据、正文、辅助资源分成三层，并说明扫描时仍需读取文件来解析 frontmatter。这能避免把“节省模型上下文”误解成“启动完全不读文件”。Backend 虚拟路径、目录层级和 Skill 名称校验也给了可操作的约束。

## 建议补充

1. 提供一份配套锁定文件。章节以 0.7.10 核对，本项目使用 0.7.8；AsyncSubAgent 仍属预览接口，最新文档也会出现当前版本不存在的字段。建议将 Python、Deep Agents、CLI、API、SDK 版本放到示例开头，并保留对应源码链接。
2. 把端口和状态目录隔离作为连续课程的默认步骤。已有 Task1 时，新例子应使用另一个端口和独立服务数据目录，避免复制默认 2024 端口或复用 checkpoint 目录。
3. 增加可自动断言的生命周期记录：启动返回时的子 run 状态、两任务同时 running、update 前后相同 thread 与不同 run、取消后的服务端终态。固定等待 8 秒容易被本地模型延迟覆盖，建议明确演示用等待时长可调。
4. 单独演示“取消 → update 续跑”，说明保留什么、重做什么。这样更容易理解任务恢复、图中断恢复与协程恢复的差别。
5. Skills 配一个相关技能和一个无关技能，记录首轮系统提示词的元数据、后续 read_file 与最终产物。用正文专有标记证明按需加载，比仅展示一份 SKILL.md 更有说服力。
6. 增加产物复核环节。本次模型执行了读取、写入与读回，但文字中仍先后出现虚构日期和检查项数量错误。建议把加载机制验收与报告事实验收分开列出，保留原稿并记录修正。

这些建议主要是补足连续项目里的复现与验收步骤。概念讲解已经提供了很好的路线，配合结构化记录会更方便定位“模型选择有误”“服务配置有误”和“工具已执行但产物不合格”等不同问题。
