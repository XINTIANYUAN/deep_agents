# Task4 学习心得

这次实验让我开始把“制定计划”和“执行计划”分别观察。首轮模型确实先调用了 `write_todos`，但后来反复搜索资料，清单一直停在 `pending`。工具存在、工具被调用和进度及时更新，是三个需要实际检查的环节。 [操作与问题复盘](learning-notes.md)

第二轮更容易让人误判。最终清单全部完成，报告也生成了，但最后的核查任务直接从待办跳到了完成状态。有几项清单声称已经保存框架笔记，文件列表里却没有三份对应产物。我因此开始把每次清单更新、工具调用参数和虚拟文件路径放在一起看，判断任务究竟做到了哪一步。

报告内容还暴露了另一个问题。搜索结果中的网站导航包含许多产品名称，模型把这些词条拼成了 Codex SDK 的能力说明。能够引用官方域名，仍然需要检查引用对应的正文。本次改为读取官方 Markdown 概览，再按正文整理报告，也在复盘中保留了前一轮的错误归因。

我理解的规划验收现在有三个落点。`todos` 展示 Agent 记录的进度，Trace 展示实际执行，报告与笔记展示产物。把三者对齐后，才能判断“完成”是否有证据支撑。后续任务即使更复杂，我也会沿用这样的检查方式。 [实测记录](experiment-results.json)
