# Task4 课程反馈

第 4 章明确说明了规划需要显式启用，也提醒读者把 `todos`、工具调用和最终报告一起检查。这次实测中的几处偏差，正好说明了这套验收方式的必要性。 [第 4 章课程正文](https://datawhalechina.github.io/deepagents-in-action/chapters/ch04-task-planning/)

1. **在完整示例中直接保存清单变化。** 建议用 `stream_mode="values"` 记录每次不同的 `todos`，运行结束后列出每项的状态序列。本次有一次运行最终全部完成，核查任务却没有出现 `in_progress`。只打印最后回答容易漏掉这一点。

2. **把“完成”的标记对应到实际产物。** 给清单中的资料收集、写报告和核查分别列出证据，例如搜索调用、笔记路径、报告正文和读回结果。这样可以看出哪些步骤有实际文件，哪些只是模型写下的进度说明。

3. **补充搜索摘要的质量检查。** 本次搜索工具拿到了官方域名页面，但摘要混入网站导航，模型将其中的 API 平台功能归到 Codex SDK。建议示例优先读取官方正文，并引导学员核对能力描述所属的具体产品。

4. **给本地小模型一个紧凑的实验版本。** 示例可以保留“模型自己列计划”，同时明确研究范围、每个框架的一次检索、笔记路径和最终核查步骤。本次收紧这些提示后，重复搜索有所减少。模型规模、提示词和资料质量对结果的影响仍需分别实测。 [可运行研究 Agent](../../examples/task4/research_agent.py)

本次使用项目锁定的 Deep Agents `0.7.8`。章节中部分中间件细节已按 `0.7.10` 更新，实验围绕实际安装版本核对规划行为。Lec 06 的 B 站链接在自动读取时返回 HTTP 412，视频内容未核验，笔记依据章节正文、官方文档和运行记录整理。 [Lec 06 视频入口](https://www.bilibili.com/video/BV1mkdwBoEDf/)
