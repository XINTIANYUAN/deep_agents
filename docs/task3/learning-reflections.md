# Task3 学习心得

Task2 我关注模型调用了几次工具。Task3 让我开始关注每次调用以后，哪些内容留在对话中，哪些被存入文件，以及下轮模型具体拿到了什么。

最直观的一次观察发生在大结果实验。工具生成了 285,492 字符的资料，LangSmith 的工具节点保存着全文。点开后面的模型节点，输入里出现了文件路径、首尾预览和省略行数，长度缩到 1,733 字符。模型随后按偏移读回目标行。我通过这条链路理解了按需取用上下文，先保留可定位的引用，再读取需要的片段。 [实验记录与截图](learning-notes.md#实验二--默认大结果卸载)

我也感受到文件内容与对话措辞之间的差别。让 Agent 写笔记以后，只有继续读回原文件、搜索指定文字，并检查真实 State，才能知道写入是否成功。工具返回的成功提示、正文和路径，各自回答不同的问题。相同的检查方式也可以用在后续研究材料和中间报告上。

Backend 对比纠正了我对“持久化”的笼统理解。复用同一个内存 Store 时，另一个线程读到了文件。启动新进程、创建新内存 Store 后，文件就读不到了。同一实验中的磁盘文件则仍然存在。今后选择 Backend，我会同时说明线程范围、进程范围以及底层存储配置，让“保存”对应一个可以复现的时间边界。 [Backend 对比结果](learning-notes.md#实验三--backend-生命周期对比)

State 的实验也说明，文件和线程状态可以一起延续。使用同一内存 Checkpointer 重建图后，原线程仍能读回笔记。要继续讨论重启恢复，就必须明确 Checkpointer 的实现与存活方式。这让我更愿意通过具体的写入、读取和重启实验理解框架行为。 [精简实测数据](experiment-results.json)
