# Task5 学习心得

这次我把任务分给两个职责明确的角色。研究员收集资料并保存发现，写手读取发现成文，主 Agent 通过两次 `task` 协调交接。主对话中能看到摘要和文件位置，研究员的源码读取、分析与任务更新记录保留在自己的上下文里。 [角色与实测记录](learning-notes.md)

共享文件的实验让我注意到路径本身也是交接内容。一次运行中，研究员写到了 `/app/handoff/findings.md`，写手却按 `/handoff/findings.md` 查找，随后读不到文件。角色名称和分工都已经正确，交接仍然失败。统一虚拟根路径后，写手才能依据实际文件继续工作。

我也区分了上下文隔离和文件访问规则。三个角色只加载了各自的 Skills，主、子 Todo 互不覆盖，但共享 Backend 中的文件仍然可读。这样的设计让大段资料可以留在文件里，委派描述只携带必要路径；需要限定写入范围时，再通过各角色自己的权限配置完成。

最后一次报告复核提醒我，子 Agent 的最终回答同样需要校验。研究员把源码中的“返回状态包含 messages 键”误读为“必须返回 ToolMessage”，写手沿用了这个说法。流水线已经跑通，错误仍会顺着摘要传递。我会同时查看角色调用、文件和关键结论，让协作结果有可以追溯的依据。 [报告复核稿](pipeline-report.md)
